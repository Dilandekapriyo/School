SKOLA – API CONVENTIONS

Status: FINAL · LOCKED · BUILD‑READY
Applies to: All backend services

1️⃣ Overview

API Style: REST

Base URL: /api/v1/

Format: JSON only

Auth: JWT (Access + Refresh)

Backend: Django REST Framework

Multi‑tenant: Yes (School‑scoped)

2️⃣ Core Principles (NON‑NEGOTIABLE)

One responsibility per endpoint

No business logic in views

Business logic lives in services/

Serializers = validation only

Permissions enforced server‑side

Frontend is never trusted

Soft deletes only (never hard delete)

All write actions are auditable

3️⃣ Authentication & IdentityAuth Endpoints

POST /api/v1/auth/login/

POST /api/v1/auth/refresh/

POST /api/v1/auth/logout/

POST /api/v1/auth/password-reset/


Required Headers

Authorization: Bearer <access_token>

Content-Type: application/json


🔐 JWT payload must include:

user_id

active_school_id

role_codes

4️⃣ Multi‑Tenancy Rule (CRITICAL)

Every school‑scoped request MUST include:

X-SCHOOL-ID: <school_uuid>


Backend Must:

Validate user belongs to the school

Validate section access if applicable

Reject cross‑school data access

Return 403 FORBIDDEN on violation

🚨 No default school inference allowed

5️⃣ Bilingual & Section Awareness

If a school is BILINGUAL:

All academic endpoints must respect section_id

Section filtering is mandatory for:

classes

subjects

schemes

assessments

students

Example:

GET /api/v1/classes/?section_id=<uuid>
